# 独立审查 / Independent review — 2026-11-07

当前结论：在已审核的游戏／ZombieBuddy版本和资格策略范围内，未发现尚未处理的正常路径阻断。仅完成源码与离线方法／真实JVM验证，没有安装、发布或游戏内验收。

Current conclusion: no outstanding normal-path blocker was found within the reviewed game/ZombieBuddy versions and eligibility policy. This is source/offline and real-JVM validation, without installation, publication, or in-game acceptance.

## 已发现并修复 / Findings addressed

1. `Bootstrap.install` 的 installed 分支原先直接返回，导致 shutdown 后同一JVM新档无法重新ready。现在该分支重新初始化canonical Runtime，保持inactive，仍需新的显式握手。The installed branch now rearms the canonical Runtime after shutdown without activating ownership.
2. 构建原先复用classes目录并按类名前缀收集，可能把已删除类／内部类带入JAR。现在每次使用全新classes目录编译打包。Each build now compiles into a fresh output directory, excluding stale classes.
3. activate成功后的 `ClearLegacyForNative` 原先不在受保护的初始化区间，异常未必进入统一撤销／回退。它现与初始同步共同保护，并增加失败回归。Post-activation legacy clearing and initial synchronization now share cleanup/fallback handling.

## 语义与兼容范围 / Semantics and compatibility

- 只改写已核对的 `Food` 方法入口／调用点；原生float年龄、FridgeFactor、FoodRotSpeed、腐败替换和删除公式保留。真实容器type、温度字段、物品归属和存档结构没有被伪装成冰箱。Only reviewed Food callsites/entry points change; native formulas and real container identity/type/ownership remain intact.
- 主模组正常保存的schema1、paid/on、token及六个Lua Double电池表与Native资格兼容。异常空洞、Java注入的非Double、未知元表／table实现保守拒绝并报告reason；不改付费记录。Normal schema1 paid records remain compatible; malformed/unknown representations fail closed with diagnostics.
- 真正通电的原生冰箱／冷冻柜优先；便携冷藏仅覆盖合法开启包及其嵌套食品作用域。Master off仍由Java拥有调度，但helper退回vanilla；不会重新启动无用的Lua食品循环。Powered native fridges/freezers take priority; master-off preserves Java ownership while delegating vanilla behavior.
- `settle` 只在显式转移／状态／保存边界调用原生年龄结算并写兼容checkpoint或清离域旧ledger；Food正常更新不逐次建立Lua食品账本。Save入口在父类序列化ModData前锚定状态，未知schema不覆盖。Boundary checkpoints also cover unsaved cold→warm transitions before API failure; no per-update food ledger is added.
- shutdown和transform失败的emergencyDisable只停用标志、清缓存，不在世界销毁后或transformer线程扫描食品。Shutdown/emergency disable never traverse or mutate Food.
