# 蘇清的冷藏升级模组 / SuQing’s Refrigeration Upgrades Mod

[中文](README.md) · [English](README.en.md)

Project Zomboid **Build 42.21 单人候选版 1.0.0-rc.2-perf.8**。Mod ID：`SuQingRefrigerationUpgrade_4221`。

为现有标准可穿戴储物装备安装永久冷藏改造，保留原容量、减重、自重、外观、装备槽位、储液组件和收纳过滤。无需普通容器升级或背包超级升级前置，可与它们共用。不会返鲜。

## 性能与可选 Java 补丁（2026-11-07）

**Lua 模式在大量冷藏食品下可能有较高的 CPU 开销，即使关闭背包也可能影响帧率。大容量随身容器或数百件冷藏食品，建议搭配[蘇清的冷藏性能补丁](https://steamcommunity.com/sharedfiles/filedetails/?id=3834960443)。** 普通工具、武器和材料不做逐件冷藏结算；发现扫描仍会遍历物品和嵌套容器，主要持续负载来自被追踪的 `Food` 类物品。

本主模组可以独立运行，不强制安装 Java。性能补丁是单独的工坊项目，Mod ID `SuQingRefrigerationNative_4221`，版本0.1.0-rc.1；需要本主模组1.0.0-rc.2-perf.8及[ZombieBuddy 2.3.4](https://steamcommunity.com/sharedfiles/filedetails/?id=3619862853)，仅审核B42.21.0单人。顺序：ZombieBuddy → 冷藏升级 → 返鲜餐盒（若使用）→ 性能补丁。

补丁由原生食品调度接管年龄、冷藏温度和冻融，停止Lua逐Tick全食品循环。总开关、已有物品、付款记录、费用和存档schema保留。Java模式采用原版 `FridgeFactor` / `FoodRotSpeed`，自定义 `RotSpeedPercent` 只在Lua模式生效。Lua模式保留原有约20游戏分钟降温和自定义年龄封顶；两种后端的温度过渡不保证完全相同。

首次按ZombieBuddy正常提示批准JAR。新增、更换、禁用或移除Java补丁必须完整退出并重启游戏，不能在运行中替换JAR。它只读取得ZB私有 `Loader.g_instrumentation`，不修改游戏JAR或关闭批准机制；精确版本和JAR/食品字节码门禁拒绝未审核组合。接管前先清算旧Lua，确认Java激活后才停止旧循环；激活前缺失或不匹配保留Lua，运行中故障有明确停用/重启边界。详见[后端说明](native-backend/README.md)。

用户单人实测及两次新日志已确认Java接管、旧Lua全扫停止和正常保存退出，用户报告明显改善；本轮没有同负载受控FPS净增百分比或联机验收。**可选Lua显示合并目前精确支持已审核的搜索增强0.1.1；搜索增强0.1.2会安全停用该显示功能。** 这不阻止Java后端接管，不放宽版本门禁来假定新包装器已支持。

原生老化、冷藏封顶、冻融、取放、开关、保存及ledger替换语义保持。571食品×8Tick模型少13704次getter调用，年龄／热量／lastAged逐项相同；真实Food方法配对微基准三进程的耗时中位数均下降，但它复用单个Food，并非571真实食品、加载世界或FPS测试。实机收益待用户验证。此版仅修改Lua，没有新增Java补丁或依赖。

## perf.3 性能维护（2026-11-07）

冷藏状态按直接容器缓存，最长一个游戏分钟；已知转移、开关、安装／拆除、加载和配置变化即时使缓存失效。放入前结清原环境、取出前结清冷藏区间，整包移动只处理相关食品子树。每 Tick 仍执行必要原生老化、冻结／解冻与冷藏封顶，保留原腐坏倍率和约20游戏分钟降温，不用整小时合并取代原生保护。

物品栏纯绘制仅在已审阅的原版／CleanUI 2.10.4及配套包装器中复用本世界时刻已完成的结算；年龄、热量、lastAged、归属、记录字段和缓存代际必须一致，复用期限不超过500真实毫秒。实际操作、未知来源或变化立即走严格入口。外部包装器替换后安全停用显示合并。

兜底发现每真实秒尝试启动，未完成队列不重启；每帧最多32项或约1ms，逐项处理而非反复完整结算全部食品。加载前原生process列表变动保护仍保留。保存前强制严格清算，失败显式报告且不推进完成时间。缓存和显示memo仅运行期存在，不更改ID、付款凭据、存档结构、容量或画质。绕过标准事件的外部冷藏状态改写最多在一分钟复核时识别，不能凭轮询回推不可证明的转移时点。

本版为本地单人候选；离线验证和用户实机FPS验收分开记录。当前源码餐盒配套版本为0.1.0-rc.8-perf.8；其精确门禁支持已审冷藏perf.1–8，未知版本不放宽。

## 安装与依赖

退出游戏并保留存档与旧版文件备份，将 `mods/SuQingRefrigerationUpgrade_4221` 整个文件夹放入用户的 `Zomboid/mods`。保留 `42` 与 `common`，先在独立单人测试档启用。不要复制整个仓库为模组目录，不要保留重复 Mod ID。

没有强制的第三方模组依赖。`loadModAfter` 为普通容器升级、EX、CleanUI、Neat Crafting 提供可选顺序提示，并不要求安装它们。原装备仍由原游戏或来源模组提供。

相关本地兼容维护见[蘇清的僵尸毁灭工程补丁合集](https://github.com/suching8848/suqing-project-zomboid-patches)。本冷藏模组没有强制依赖该仓库的某个补丁；根据实际安装的来源模组选取适用项，不要整包全部启用。原生换位与特殊装备转换仍需实际验收。

## 使用

1. 目标装备卸下、移出双手，放入主物品栏，清空普通物品；带储液组件时排空全部液体。
2. 准备非收藏材料：**6 节电池、4 电线、4 电子废料、2 小金属板**。电池按实体个数消耗，允许部分电量；没有额外技能门槛或持续耗材。
3. 原生制作 → **蘇清·冷藏升级 → 安装蘇清冷藏升级**。成功后默认开启，永久续航；取消不扣料。
4. 对已改造装备右键选择 **开启制冷 / 关闭制冷**。切换允许穿戴，但装备须处于角色主物品栏；右键不提供安装、拆除或自绘悬浮提示。
5. 拆除前同样卸下、清空、排空液体。在同一制作分类拆除，返还有效实付材料的 **50%：3 电池、2 电线、2 电子废料、1 小金属板**。电池按付款凭据保留剩余用量，不会变成满电。

目标装备可以收藏，收藏材料不支付。原容量/超级容量记录和其他 ModData 保留。

## 温度、沙盒与支持范围

Lua模式下，常温食物的归一化温度 1 降至 0.2 约需 20 个游戏分钟；热食更久。关闭后由原生机制回温。已有 rc.1 冷藏记录、开关和电池账本继续适用，无需再次付费。

Lua模式沙盒“蘇清的冷藏升级”：总开关默认开；腐坏速度 **0–100%，默认 20%**，相对世界基础腐坏速度。0 保持当前新鲜度，100 恢复常温速度，不倒退食物年龄。原生冰箱、冷冻和多层冷藏不重复相乘；不主动冻结，不修复烧焦、中毒、污染或改变生熟和吃剩量。本版不提供旧档沙盒编辑器。

自动识别有实际装备槽位的标准 `InventoryContainer`。专用弹药、枪套、钥匙、钱包过滤不取消。自定义过滤器需用允许的食物做正向确认：先放入实际允许的食物，打开菜单检查，再清空安装；不会因苹果被拒绝就推断全部食物不可放。虚拟仓库、没有实际容器的衣物口袋不保证通用支持。窄范围适配接口：`SuQingRefrigeration.RegisterContainer(fullType, true/false)`。

## 停用与验证边界

停用不会自动返料，也不删除装备、食物或改造记录。停用期间食物按普通腐坏处理；重新启用后可识别记录。需要彻底移除时，保持启用并在游戏内逐件拆除、保存退出后停用，无需覆盖世界文件。

历史记录中用户确认了 rc.1 传奇背包制冷与开关正常。rc.2/perf.1 的原生制作入口、温度渐变、世界卸载、车内、特殊转换、暂停/睡觉/加速和实际性能仍需集中游戏验收。开发记录包含 Kahlua 与本机游戏原生类离线回归；模拟负载改进不代表实机 FPS 提升。多人和专用服务器未验证。
